## Backend findings (crm-api)

- **OpenAPI now exists** (`api.json`, exported by dedoc/scramble, 106 paths). Types are still hand-written Zod schemas, but `apps/app/tests/contract/api-contract.test.ts` checks them against the spec: every field a schema expects must be documented, and every field it requires must be documented as required (27 checks: employee, branch, department, team, audit log, org-chart node, notification, user, tenant). Re-export `api.json` after backend changes and run `pnpm test`.
- Fixed while building sales (affected the whole app): avatar initials were muted grey instead of white because `tailwind-merge` read our custom `text-caption`/`text-small` font sizes as colours and dropped `text-white`. `cn` now knows the type scale (regression test in `tests/ui/cn.test.ts`).
- The spec also shows what the API already offers that the UI does not use yet: notifications (now wired to the bell), roles and permissions (`/roles`, `/permissions`, `/employees/{id}/roles`), reports (`/reports/overview`, `/reports/agent-performance`), leads/deals/tasks/pipeline, units/projects/buildings, lead and CSV import/export (leads only), security policy, export requests. These are the next sprint's screens.
- `lang/` has `ar` and `en`; no JSON message bundle to reuse for the frontend.
- Resources exist for: User, Tenant, Branch, Department, Team, Employee, OrgChartNode, AuditLog, SecurityPolicy.
- **Gaps vs. the brief** (to confirm against running API):
  - No `GET /employees/{id}/activity` — profile "recent activity" must use `GET /audit-logs?auditable_type=…&auditable_id=…`.
  - No monthly-target field on Employee (profile "target progress" card) → placeholder until Leads/Deals exist.
  - No KPI/stats endpoint for the 4 employee KPI cards → derive from `status` filtered list `meta.total` calls (4 cheap requests) until a stats endpoint exists.
  - No "move department" endpoint → use `PUT /departments/{id}` with `parent_id`.
  - Org chart has no "by department" mode (`/org-chart` accepts only `root_id`) → by-department layout built client-side from `/departments/tree`.
  - Employee list has no `sort` param (IndexEmployeeRequest) → sorting UI disabled for employees until added.
  - Offboard "what will be transferred" counts not exposed → dialog shows generic text until Leads exist.
  - Audit log has no `search`/free-text, and no `module` list endpoint.
  - `POST /employees` (and PUT) return the model un-refreshed: `status` and `is_owner` are `null` in the response (the lists are correct). Found by the e2e test: a strict schema made a successful create look like a failure. The frontend now validates only `id` on writes; the backend should `->refresh()` before returning.
  - Register has `password_confirmation` (`confirmed` rule) — form must send it.

## Decisions

- pnpm is not installed on this machine → installed via npm (12.16.1).
- TypeScript pinned to ~6.0.3 (typescript-eslint peer range is <6.1); ESLint pinned to 9.
- Dependency boundaries use core `no-restricted-imports` per folder (not eslint-plugin-boundaries); RTL rule is `no-restricted-syntax` regex. Both live in `packages/config/eslint.mjs`. Still to prove with a deliberate-violation test.
- `baseUrl` dropped from tsconfig (deprecated in TS 6); `paths` alone is enough.
- Editing through lean-ctx `ctx_patch` (needs `lean-ctx allow-path D:/mkdir/projects/crm-web`, done).
- Latest stable (checked 2026-10-30 via npm): next 16.4.3, react 19.3.1, turbo 2.11.10, tailwindcss 4.3.3, next-intl 4.14.9, @tanstack/react-query 5.105.0, nuqs 2.10.2, zod 4.6.7, typescript 7.0.2.

- Next 16 renamed `middleware.ts` to `src/proxy.ts`; the route guard lives there (deviation from the folder spec, same role).
- shadcn files get `'use client'` on every component (generated with rsc:false; without it the server layout crashes on Radix contexts).
- shadcn CLI mis-added an npm package `cn` and a bad `border-ring` rewrite; both fixed. Re-running the CLI later needs the same cleanup.
- pnpm 12 blocks dependency build scripts; approved only @parcel/watcher, @swc/core, unrs-resolver.
- 2FA skipped on the backend per owner: login is email + password only.

- Shell gaps by design: sidebar count badges need data from other features (boundary rules forbid it in `shared/`); command palette (Ctrl K) and company switcher are display-only. The notifications bell is live (unread count polled every 60s, list on open, mark one / all as read); `AppShell` takes it as a slot because `shared/` cannot import features.
- `useCurrentUser`/`useCan`/`<Can>` read `/auth/me` through `AuthProvider`; owners pass every `useCan` check (`is_owner`), otherwise the `access.permissions` list decides.

- TanStack Table is v9 (new API: `useTable`, feature registry, `helper.columns([...])`); URL state via nuqs, table-internal state only for selection and column visibility.
- Fixed during phase 5: `html{font-size:14px}` was shrinking every rem token (now `body` only); `table` no longer forces Inter (would break Arabic); RTL lint rule no longer flags prose like "left-to-right".
- Known small issue: no favicon yet (browser logs a 404 for `/favicon.ico`).
- Backend marks masked audit values with the literal `[hidden]`; `AuditDiff` swaps it for the localized label.

- Branches API facts: list takes `search`, `is_active`, `per_page` (default 25, max 100), no sort; deleting a non-empty branch is a 422 keyed `branch`, shown inline in the confirm dialog instead of a toast.
- URL-synced tables need a Suspense boundary (nuqs reads search params); one boundary with a skeleton lives in `(dashboard)/layout.tsx` for every page.
- `features/organization/employees` exists as a stub (types, query keys, `useEmployeeOptions`) so pickers can reuse it; the full employees feature is phase 10.

- Departments API facts: `/departments/tree` is unpaginated with nested `children`; the list takes `search`, `branch_id`, `parent_id` (empty = roots), `per_page`; "move" is `PUT { parent_id }` because updates are partial (`PartialData`), and `null` means top level; delete of a non-empty department is a 422 keyed `department`, a cycle is a 422 keyed `parent_id`.
- Shared pieces added in phase 8: `FormAlert` (was duplicated four times), `CodeLabel` (isolates codes as LTR without flipping the paragraph's alignment, which was visibly wrong in Arabic), `SelectField.noneLabel` and `SelectOption.depth` (indent via start padding: a text prefix like "—" is reordered by bidi in RTL).
- Prettier + the import-sort rule need two `eslint --fix` passes to settle; run it twice.

- Teams API facts: list takes `search`, `department_id`, `per_page`; `department_id` is required on create; deleting a team with members is a 422 keyed `team`. Departments now exports `useDepartmentOptions` for other features' pickers.
- First request to a freshly added route in `next dev` can take ~10s (compile); the page shows skeletons meanwhile, it is not a bug.

- Employees API facts: list filters `search, status, branch_id, department_id, include_sub_departments, team_id, manager_id, per_page`; no creation-date or sort params; `direct_reports_count` is only on the detail response; `employee_code`, `hired_at`, `commission_rate` are empty in the demo data. Audit entries store raw ids (`team_id: 5`) and `auditable_type: "employee"`; the profile resolves ids to names client-side via cached lists. `/org-chart` returns only active employees.
- Fixed on sight in phase 10: team picker showed identical "Team A"/"Team B" for different departments (labels now include the department); status diff showed raw `active → suspended` (now localized); profile tabs were stretched across the card.
- Audit log now contains my test entries (a suspend/activate pair on employee 14, plus earlier branch/department/team create-delete pairs); no business data was left changed.
